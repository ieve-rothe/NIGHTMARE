# Commands Reference

NIGHTMARE provides a suite of slash commands and input modes to inspect context, manage file pinning, switch themes, and orchestrate autonomous plans.

## Quick Reference

| Command | Arguments / Subcommands | Description |
|---|---|---|
| `/help` | - | Display the help reference. |
| `/add` | `<path>` | Pin a file into the active token context. |
| `/drop` or `/rm`| `[path]` | Unpin a specific file, or drop all if no path is given. |
| `/clear` | - | Clear the screen and wipe turn history (retains pinned files). |
| `/cls` | - | Clear terminal screen ANSI display without wiping history. |
| `/save` | `[path]` | Export pristine RAM transcript to Markdown. |
| `/review` | - | Inspect the assembled system prompt, pinned files, and token usage. |
| `/thinking` | - | View model internal chain-of-thought from the last turn. |
| `/prompt` | `[edit [text]]` | View or edit the in-memory system prompt. |
| `/paste` | - | Enter multi-line input paste mode. |
| `"""` | - | Trigger multi-line input mode (equivalent to `/paste`). |
| `/model` | `[name]` | Inspect or change the active LLM model. |
| `/theme` | `[name]` | List available themes or switch the active UI theme. |
| `/mode` | `sprint`, `pace`, `step` | Configure plan execution pacing and thermal limits. |
| `/plan` | `run`, `status`, `report`, `review` | Manage autonomous plan execution. |
| `/exit` or `/quit`| - | Exit the session. |

## File and Context Management

### `/add`
Pins a workspace file into the model's active context. This ensures the file contents are always prepended to the prompt.
```bash
/add src/core/main.cr
```

### `/drop` and `/rm`
Removes a pinned file from the context. If no path is provided, it drops **all** pinned files.
```bash
/drop src/core/main.cr
/drop
```

### `/clear` and `/cls`
- `/clear` wipes the conversation history (turns) and clears the screen, but **retains** the system prompt and any pinned files.
- `/cls` strictly clears the terminal ANSI display, leaving history intact.

### `/save`
Exports the pristine, in-memory conversation transcript to a Markdown file. If no path is specified, defaults to `transcript.md` in the workspace state directory.
```bash
/save logs/debug_session.md
```

## System Prompts and Inspection

### `/prompt`
Displays the current in-memory system prompt.
- `/prompt edit` prompts for an inline edit. It integrates with your `$EDITOR` environment variable for advanced editing.
- `/prompt edit <text>` immediately replaces the system prompt with the provided text.
```bash
/prompt edit You are a senior security engineer.
```

### `/review`
Displays a comprehensive context assembly review. This shows exactly what is being sent to the LLM.
- Complete system prompt
- Pinned files block
- Full conversation history (turns)
- Token budget estimates (system, pinned files, active turn)
- Current token calibrator divisor

### `/thinking`
Outputs the internal chain-of-thought (reasoning) generated by the model during the previous turn. Useful for debugging model hallucinations or misalignments.

## Multi-line Input Modes

Multi-line mode is essential for pasting large stack traces, JSON blobs, or code blocks without triggering premature execution on `Enter`.

### `/paste` and `"""`
Type `/paste` or `"""` to activate multi-line mode. Once active, paste your text, then type `"""` or `/end` on a new line to submit.
```text
> """
 ↳ Multi-line mode active. Paste your text, then type '"""' or '/end' on a new line to send.
def hello_world
  puts "Hello"
end
"""
 ↳ Text captured. Processing...
```

**Limits:**
- Maximum Lines: `2000` (`MAX_MULTILINE_LINES`)
- Maximum Characters: `200000` (`MAX_MULTILINE_CHARS`)

If the limit is exceeded, the input is gracefully truncated to prevent context overflow.

## Plan Orchestration

The `/plan` command suite manages autonomous plan execution within isolated Git worktrees. (See [Plan Orchestrator](08-plan-orchestrator.md) for deeper architecture).

### `/plan review`
Pre-flight linter. Checks a plan JSON file for cyclic dependencies, missing targets, or schema warnings without executing.
```bash
/plan review my-plan.json
```

### `/plan run`
Provisions an isolated Git worktree and executes the plan autonomously.
```bash
/plan run my-plan.json
```

### `/plan status`
Inspects the active or most recently completed plan run state. Displays real-time status of each plan item.
```bash
/plan status
/plan status run_abc123
```

### `/plan report`
Generates a comprehensive telemetry and test diff report for a plan run. Includes token usage, shell command durations, error history, and proposed follow-up targets.
```bash
/plan report
```

## Pacing and Thermal Controls

### `/mode`
Configures the execution pacing for autonomous plans and loops.
- `sprint`: 0s inter-item delay, maximum throughput.
- `pace`: 3.0s inter-item delay, 0.5s inter-turn delay, GPU thermal tripwire active.
- `step`: 6.0s inter-item delay, 1.0s inter-turn pacing.
```bash
/mode pace
```

## UI and Preferences

### `/theme`
Lists available UI themes or switches the active syntax formatting theme. Available themes: `cyberpunk`, `outrun`, `phosphor`, `classic`.
```bash
/theme outrun
```

### `/model`
Inspects or switches the active LLM model.
```bash
/model qwen2.5-coder:7b
```
